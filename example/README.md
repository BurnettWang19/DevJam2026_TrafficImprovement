# 經典案例資料夾

分析流程在最後一步會來這裡找一個「與被分析路口同類型、且解決類似問題」的良好設計案例，
連同圖片一起回傳給前端展示。

## 怎麼新增案例

1. 把圖片放進這個資料夾（`.jpg` / `.png` 都可以）。
2. 在 `index.json` 的陣列裡加一筆：

```json
{
  "id": "唯一英文代號",
  "name": "案例名稱",
  "country": "國家或來源",
  "intersection_type": "正交路口",
  "image": "檔名.jpg",
  "tags": ["人行道退縮", "小轉彎半徑"],
  "problems_addressed": ["這個案例解決了什麼問題"],
  "summary": "一兩句說明這個設計做了什麼",
  "why_it_works": ["為什麼有效，一點一句"]
}
```

## 欄位說明

| 欄位 | 必填 | 說明 |
|---|---|---|
| `id` | ✅ | 唯一代號 |
| `name` | ✅ | 顯示在前端卡片上的標題 |
| `intersection_type` | ✅ | 必須與路口分類 Agent 的輸出一致，見下表 |
| `image` | | 檔名。留空或檔案不存在時前端只顯示文字 |
| `tags` | | 比對用關鍵字，越貼近實際問題描述命中率越高 |
| `problems_addressed` | | 比對用，也會顯示在前端 |
| `summary` | ✅ | 設計做法 |
| `why_it_works` | | 為什麼有效（前端條列） |

## `intersection_type` 可用值

與 `backend/prompts/20_intersection_type.md` 定義一致：

- `正交路口`
- `圓環路口`
- `多道路匯入路口`
- `T型路口`
- `錯位路口`
- `匝道匯入路口`
- `非路口`

> 比對規則：類型相同 +5 分，`tags` / `problems_addressed` / `summary` 每命中一個問題關鍵字 +1 分，取最高分者。
> 完全沒命中時退而取同類型的第一筆；連同類型都沒有就不顯示案例（不會擋住流程）。
